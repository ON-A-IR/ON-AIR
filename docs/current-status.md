# ON-AIR 현재 상태

이 문서는 현재 ON-AIR 프로젝트에 적용된 대본 생성과 TTS 동작을 정리한 문서입니다.

## 1. TTS 현재 상황

### 기본 설정

- 기본 제공자: `Piper`
- 환경 변수: `TTS_PROVIDER=piper`
- 실행 파일: `C:\ONAIR\piper\piper\piper.exe`
- 현재 모델: `C:\ONAIR\piper\models\ko_KR-kss-medium.onnx`
- 언어: 한국어
- API 키: 필요 없음
- 처리 위치: 로컬 Windows PC

### 현재 Piper 모델의 특징

현재 한국어 KSS 모델은 단일 화자 모델입니다.

```json
{
  "num_speakers": 1
}
```

따라서 진행자마다 완전히 다른 목소리를 내는 다중 화자 기능은 현재 모델에서 사용할 수 없습니다.

### 1인 라디오

대본에 한 명의 진행자만 있으면 전체 대본을 현재 Piper 음성 하나로 읽습니다.

대본의 다음 요소는 음성으로 읽지 않습니다.

- `[00:00 오프닝]` 같은 섹션 표시
- `민서:`, `도윤:` 같은 진행자 이름

### 2인 라디오

현재 모델은 단일 화자 모델이므로 두 진행자의 대사를 모두 같은 Piper 목소리로 읽습니다.

대신 다음 처리를 적용합니다.

- 진행자 이름 제거
- 대사 순서 유지
- 대사 사이 짧은 무음 삽입은 다중 화자 모델을 사용할 때만 적용
- Windows SAPI 음성으로 자동 전환하지 않음

나중에 `num_speakers`가 2 이상인 호환 모델을 사용하면 `PIPER_SPEAKER_A`, `PIPER_SPEAKER_B` 설정으로 화자를 나눌 수 있도록 코드가 준비되어 있습니다.

### TTS 제공자 동작

현재 `.env`가 `TTS_PROVIDER=piper`이면 Piper 오류가 발생했을 때 Windows 음성으로 조용히 대체하지 않고 오류를 표시합니다.

`TTS_PROVIDER=auto`를 사용하는 경우에만 다음 순서로 대체됩니다.

1. Piper
2. ElevenLabs API 키가 있을 때 ElevenLabs
3. Windows SAPI

### 분위기와 감정 표현

Piper KSS는 감정 라벨을 직접 이해하는 모델이 아니므로, 현재는 방송 톤을 음성 운율 설정으로 보정합니다.

- 캐주얼: 자연스러운 기본 속도와 변동성
- 포멀: 조금 느리고 안정적인 전달
- 유쾌: 조금 빠르고 활기찬 전달
- 차분: 느린 속도와 낮은 변동성
- 요약·토론·비평 형식: 형식에 맞게 말속도와 변동성을 추가 보정

이 보정은 목소리를 완전히 다른 감정 연기로 바꾸는 기능은 아니지만, 같은 Piper 모델에서도 방송 분위기에 맞는 속도와 운율 차이를 만듭니다.

### XTTS 기능

Coqui XTTS는 메인 라디오 TTS와 별도의 목소리 테스트 기능으로 연결되어 있습니다.

- 목소리 샘플 업로드
- 짧은 한국어 문장으로 음성 복제 테스트
- API 키 없이 로컬 실행 가능
- CPU에서는 생성 시간이 오래 걸릴 수 있음

## 2. 대본 현재 상황

### 생성 방식

대본 생성은 다음 두 경로를 사용합니다.

- 기본 오프라인 생성기
- Ollama 로컬 모델 연동

Ollama가 없어도 기본 오프라인 생성기로 앱이 동작합니다. Ollama를 사용하는 경우에도 외부 API 키는 필요하지 않습니다.

### 지원 형식

- 심층 분석: 주제의 배경, 실제 장면, 장점과 한계, 정리
- 요약: 핵심 내용을 빠르게 전달하는 1인 브리핑
- 비평: 장점과 아쉬운 점을 나누어 살펴보는 1인 진행
- 토론: 두 진행자가 긍정적인 관점과 우려되는 관점을 나누어 대화

### 주제 반영 방식

대본은 키워드를 모든 문장에 반복해서 넣는 방식이 아니라 다음 정보를 바탕으로 내용을 구성합니다.

- 주제의 핵심 대상
- 실제로 떠올릴 수 있는 장면
- 주제와 관련된 사례
- 선택하거나 실행할 수 있는 방법
- 기대 효과와 주의할 점
- 마지막에 기억할 핵심 메시지

일부 자주 사용하는 주제는 전용 내용 묶음을 사용하고, 그 외의 주제는 단어 분석과 일반화된 주제 정보로 내용을 구성합니다. Ollama가 켜져 있고 사용하도록 설정된 경우에는 새로운 주제에 대해 로컬 모델이 섹션과 대사를 제안할 수 있습니다.

### 방송 길이

사용자가 선택한 5분, 10분, 15분 등의 목표 길이에 맞춰 섹션을 먼저 만든 뒤 부족한 분량을 주제 관련 후속 질문과 설명으로 확장합니다.

다만 표시되는 길이는 실제 오디오 재생 시간의 보장이 아니라 텍스트 기준 예상 시간입니다. 실제 재생 시간은 다음 요소에 따라 달라질 수 있습니다.

- Piper 음성 속도
- 문장 길이와 띄어쓰기
- 대사 사이 무음
- 컴퓨터 성능

### 대본 기본 진행자

방송 톤에 따라 기본 진행자 이름이 선택됩니다. 현재 대본에는 두 진행자가 표시될 수 있지만 TTS에서는 이름을 제거합니다.

요약과 비평 형식은 기본적으로 1인 진행 흐름을 사용하고, 심층 분석과 토론은 2인 대화 흐름을 사용합니다.

### 참고 자료 입력

소스 입력란은 현재 링크의 실제 내용을 자동으로 읽는 기능이 아니라, 사용자가 입력한 메모나 참고 방향을 대본 구성에 반영하는 용도입니다.

## 3. 현재 실행 방법

프로젝트 루트에서 프론트엔드와 백엔드를 한 번에 실행합니다.

```powershell
Set-Location C:\ONAIR\ON-AIR
npm.cmd run start
```

접속 주소:

```txt
http://127.0.0.1:5173/
```

백엔드 상태 확인:

```txt
http://127.0.0.1:8000/api/health
```

정상 응답:

```json
{"status":"ok"}
```

## 4. 변경 후 확인할 점

- `backend` 파일을 수정한 뒤에는 백엔드를 재시작해야 합니다.
- `src` 파일은 Vite 개발 서버가 실행 중이면 새로고침 또는 HMR로 반영됩니다.
- `.env`의 `TTS_PROVIDER`가 `piper`인지 확인합니다.
- Piper 모델 파일과 `.onnx.json` 파일이 함께 있는지 확인합니다.
- Windows 음성이 들리면 브라우저가 아니라 `/api/tts` 오류와 Piper 경로를 먼저 확인합니다.
